The planned experience

From permission to a careful file check.

stika is designed to test one specific question: does a TikTok-authorized direct-message export contain the exact sticker as a separate media file?

Four steps

What happens in the planned flow

01

Review the request

Before leaving stika, the user sees that the request is one-time, read-only, and used to look for the original sticker file.

02

Choose on TikTok

TikTok hosts the sign-in and consent step. The user can approve or cancel there. stika does not ask for the TikTok password.

03

Inspect the export

If authorized and available, stika checks the export for separate image or video files. Message text is not used to recreate a sticker.

04

Explain the result

If no exact original file can be confirmed, the app says so. WhatsApp handoff is offered only after an eligible sticker pack is supported.

Data request

One-time and read-only

The planned permission is for a single direct-message export. stika will not send or reply to messages and does not need ongoing access for this check.

File handling

Temporary inspection

The development server is designed to inspect the export in memory and report file counts without returning message text or file names to the app. The current build does not request an export.

Current state

Preview, not transfer

Login Kit and Data Portability approvals are not in place. WhatsApp sticker-pack handoff is still being built. The present app demonstrates the intended flow only.

Regional availability

Subject to TikTok

TikTok currently describes Data Portability API coverage for people in the EEA and UK. Other regions may not be eligible to use this export path.
